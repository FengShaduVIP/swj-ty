> 适用协议：`嘉佰达软件板通用协议-蓝牙修正-20231216 V12`（PDF 第 13–19 页）  
> 适用范围：本上位机 `serial-modbus-tool`（Electron + Vue3 + TypeScript）中寄存器 40 / 41 的处理  
> 口径说明：本文档以 **PDF 协议原文为权威**，寄存器号、位域拆分、档位换算均按 PDF 描述；

## 0. 概述

- 这两个参数都属于 **0xFA 参数寄存器**，各占 **1 个 16 位字（2 BYTE，大端）**。
- 它们是「**复合寄存器**」：单个 16 位字内同时编码两类信息——**保护值档位**与**延时档位**。
- PDF 定位（第 13–14 页参数序号表）：

| 寄存器号 | 参数名      | 长度     | 说明      |
| ---- | -------- | ------ | ------- |
| 40   | 二级过流保护设置 | 2 BYTE | 见 IC 类型 |
| 41   | 短路保护设置   | 2 BYTE | 见 IC 类型 |
| 42   | 硬件过欠压延时  | 2 BYTE | 见 IC 类型 |
| 43   | 短路释放延时   | 2 BYTE | 单位 S    |

- 芯片类型（`jbd-params.ts` 的 `CHIP_TYPES`）：

| 类型值 | 方案          |
| --- | ----------- |
| 0   | TI 方案       |
| 1   | 凹凸 7717     |
| 2   | 新塘/松下 49522 |
| 3   | 中颖 309      |
| 4   | 中颖 303      |
| 5   | 集澈 DC10XX   |
| 6   | OZ3714      |

> ⚠️ **核心认知**：PDF 第 17 页原文明确把这两个寄存器的「保护值」定义为 **电压值（mV）**（如凹凸短路 `20*SCD_T+20` mV、中颖过流对应值(mV)），并非电流(A)。
> 保护 IC 的阈值本质是比较**检流电阻两端的压降**，故要在界面折算成电流(A)需用 `电流(A) = 电压(mV) / 检流电阻(mΩ)`，检流电阻见寄存器 28（PDF 第 12 页寄存器 28「检流电阻值」）。
> 佐证：用户提供的凹凸上位机截图显示短路保护值 200/400/…/2000 A，恰为 PDF 公式 `20*SCD_T+20` mV ÷ **0.1 mΩ** 所得——说明该设备检流电阻=0.1 mΩ，且嘉佰达工具正是读取检流电阻后显示 A。
> 当前代码直接把档位显示成「50+30·N (A)」是简化近似，与 PDF 不符（见第 4 节）。

## 1. 协议权威规格（PDF 第 16–19 页）

### 1.1 位域布局（IC 类型 1~6，统一 8 位布局）

两个寄存器均为 16 位，但有效信息位于 **低 8 位（BIT7..0）**，高 8 位（BIT15..8）为 0：

| 寄存器           | BIT7   | BIT6   | BIT5   | BIT4   | BIT3   | BIT2   | BIT1   | BIT0   |
| ------------- | ------ | ------ | ------ | ------ | ------ | ------ | ------ | ------ |
| 二级过流保护设置 (40) | OCD_T3 | OCD_T2 | OCD_T1 | OCD_T0 | OCD_D3 | OCD_D2 | OCD_D1 | OCD_D0 |
| 短路保护设置 (41)   | SCD_T3 | SCD_T2 | SCD_T1 | SCD_T0 | SCD_D3 | SCD_D2 | SCD_D1 | SCD_D0 |

- **保护值档位（level）**：BIT7..4（低字节高半字节），范围 0~15。
  - 二级过流 → `OCD_T`；短路 → `SCD_T`。
- **延时档位（delay）**：BIT3..0（低字节低半字节），范围 0~15。
  - 二级过流 → `OCD_D`；短路 → `SCD_D`。

**权威拆分公式（解析用）：**

```ts
// raw：从 0xFA 读到的 16 位原始值
const level = (raw >> 4) & 0x0f   // BIT7..4：保护值档位
const delay = raw & 0x0f          // BIT3..0：延时档位
```

**权威合成公式（下发用）：**

```ts
const raw = ((level & 0x0f) << 4) | (delay & 0x0f)   // 高半字节=level，低半字节=delay
```

> IC 类型 0（TI）布局不同（见 1.3 表末），其档位位数是 3 位而非 4 位，合成时需按对应 bit 分布，不能套用上面的统一公式。

### 1.2 档位 → 物理量（按芯片类型查表）

下表中：

- **二级过流**的保护值单位是 **mV（电压阈值）**，延时单位是 **mS**。
- **短路**的保护值单位是 **mV（电压阈值）**，延时单位是 **µS**。
- 表中「公式」列可直接用档位 `T`/`D` 计算；「查表」列给出 0~15 共 16 档的对应值。

#### 1.2.1 二级过流保护（OCD_T → mV，OCD_D → mS）

## 2. 如何解析（读寄存器 → 显示物理量）

### 2.1 读取流程（无需工厂模式）

读参数命令 `0xFA` 的读取**不需要**工厂模式（仅写入需要）。寄存器号为 2 BYTE 大端：

- 二级过流保护设置 → 寄存器 40 = `0x0028`
- 短路保护设置 → 寄存器 41 = `0x0029`

**读取帧（主机→BMS）：** `DD A5 FA 03 [regHi] [regLo] [count=01] [校验] 77`

示例（读寄存器 40）：

```
DD A5 FA 03 00 28 01 FE DA 77
```

（校验 = `calcChecksum([0xFA,0x03,0x00,0x28,0x01])` → `0xFEDA`，详见附录）

示例（读寄存器 41）：

```
DD A5 FA 03 00 29 01 FE D9 77
```

**响应帧（BMS→主机）：** `DD FA 00 LEN [regHi] [regLo] [count] [rawHi] [rawLo] [校验] 77`

- `regHi/regLo`：回显的寄存器号（0x0028 / 0x0029）
- `count`：寄存器数量（此处 = 0x01）
- `rawHi/rawLo`：该寄存器 16 位原始值（大端）

### 2.2 解析步骤（pseudocode）

```ts
// 1) 从响应帧取出 16 位原始值（大端）
const raw = (resp.data[3] << 8) | resp.data[4]   // 对应 parseParamResponse()

// 2) 按权威位域拆分（低字节，高半字节=保护值，低半字节=延时）
const level = (raw >> 4) & 0x0f   // 二级过流→OCD_T；短路→SCD_T
const delay = raw & 0x0f          // 二级过流→OCD_D；短路→SCD_D

// 3) 按芯片类型映射为物理量（见 1.2 表）
const chipType = /* 来自 0x00 芯片类型读取 */
const thresholdMv = scdLevelMv(chipType, level)   // 见下，短路用 SCD_T 公式
const delayUs     = scdDelayUs(chipType, delay)    // 见下，短路用 SCD_D 公式
// 二级过流的保护值同样先得 mV，需折算电流时： currentA = thresholdMv / shuntMOhm
```

> 1~3 步与 `JbdParamConfig.vue` 的 `readField` 中 `f.kind==='scd'` 分支逻辑对应，  
> 但**拆分公式和换算函数需按本文第 1 节修正**（当前 `splitScd` 与简化公式不符，见第 4 节）。

## 3. 如何下发（写寄存器 → 设备）

### 3.1 写入流程（需工厂模式）

写参数**必须先进工厂模式**，写完再退出。

1. **进入工厂模式**：`DD 5A 00 02 56 78 [校验] 77`（默认密码 `0x5678`）
2. **写参数帧**：`DD 5A FA [2N+3] [regHi] [regLo] [N=01] [rawHi] [rawLo] [校验] 77`
   - 二级过流写寄存器 `0x0028`；短路写寄存器 `0x0029`
   - `raw` = 合成后的 16 位值（见 3.2）
3. **响应**：`DD FA 00 03 [regHi] [regLo] [N]`，状态 `0x00` 表示成功（`0x81` 表示未进工厂模式等）
4. **退出工厂模式**：`DD 5A 01 02 28 28 [校验] 77`

> 本项目的 `autoFactory` 模式会在 `writeField` 写前自动进工厂、写后自动退出。

### 3.2 合成下发的 16 位值（关键）

界面通常把「保护值」和「延时」拆成两个控件（peer 字段）。**下发前必须合回一个 16 位字**：

```ts
// level：保护值档位（0~15）；delay：延时档位（0~15）
// 权威布局：低字节高半字节=level，低字节低半字节=delay
const raw = ((level & 0x0f) << 4) | (delay & 0x0f)

// 下发字节（大端）
const rawHi = (raw >> 8) & 0xff
const rawLo = raw & 0xff
// 帧：DD 5A FA 05 00 28 01 rawHi rawLo [校验] 77   （二级过流，reg=0x0028）
//      DD 5A FA 05 00 29 01 rawHi rawLo [校验] 77   （短路，reg=0x0029）
```

> ⚠️ 若芯片类型为 **0（TI）**，档位位数不是 4 位（OCD_T 4 位 / OCD_D 3 位；SCD_T 3 位 / SCD_D 2 位，且含 RSNS 位），  
> 合成时必须按其 bit 分布（见 1.2 表末），不能直接套用上面统一公式。当前项目未对 TI 方案做区分。

### 3.3 写入示例

设芯片为松下(2)，要把「二级过流」设为档位 5、延时档位 3：

```
level = 5 (OCD_T=5 → 20·5+10 = 110 mV)
delay = 3 (OCD_D=3 → 20·3+10 = 70 mS)
raw   = (5<<4) | 3 = 0x53
帧：DD 5A FA 05 00 28 01 00 53 [校验] 77
```

### 4.2 参考实现（已合并进 jbd-params.ts）

```ts
// ===== 复合保护寄存器（寄存器 40=二级过流 / 41=短路）=====
// 权威：16 位字有效在低字节；高半字节=保护值档位，低半字节=延时档位

export function splitScd(raw: number): { level: number; delay: number } {
  const v = raw & 0xffff
  return { level: (v >> 4) & 0x0f, delay: v & 0x0f }   // ✅ 修正自 (v>>8)&0x0f
}

export function combineScd(level: number, delay: number): number {
  return (((level & 0x0f) << 4) | (delay & 0x0f)) & 0xffff
}

// 二级过流保护值(mV) 按芯片查表
const OCD_MV: Record<number, number[]> = {
  1: Array.from({ length: 16 }, (_, t) => 10 * t + 5),                 // 凹凸
  2: Array.from({ length: 16 }, (_, t) => 20 * t + 10),                // 松下
  3: [20,30,40,50,60,70,80,90,100,110,120,130,140,160,180,200],      // 中颖309
  5: [4,10,16,21,28,33,38,44,50,55,61,67,73,78,84,90],               // 集澈
  6: Array.from({ length: 16 }, (_, t) => 10 * (t + 1)),              // OZ3714
}
// 短路保护值(mV) 按芯片查表
const SCD_MV: Record<number, number[]> = {
  1: Array.from({ length: 16 }, (_, t) => 20 * t + 20),
  2: Array.from({ length: 16 }, (_, t) => 40 * t + 20),
  3: [50,80,110,140,170,200,230,260,290,320,350,400,500,600,800,1000],
  5: [19,30,41,53,64,75,87,98,110,120,132,143,155,166,177,190],
  6: Array.from({ length: 16 }, (_, t) => 40 * (t + 1)),
}

export function overcurrentMv(chip: number, t: number): number {
  return OCD_MV[chip]?.[t & 0x0f] ?? 0
}
export function shortCircuitMv(chip: number, t: number): number {
  return SCD_MV[chip]?.[t & 0x0f] ?? 0
}
// 折算电流：currentA = mv / shuntMOhm（shuntMOhm 来自寄存器 28）
```

> 延时档位建议同样按 1.2 表做成 `OCD_DELAY_MS[chip]` / `SCD_DELAY_US[chip]` 查表，  
> 而非当前的 `scdDelayMs` 统一公式。TI(0) 与中颖303(4) 需硬件实测后补全。

## 附录：帧结构与校验速查（详见 `doc/嘉百达协议.md`）

- **大端**：所有 16 位数据高字节在前。
- **校验和**：`calcChecksum([命令码, 长度, 数据])` → 求和 → 二补码（取反+1）→ 高位在前。
  ```ts
  export function calcChecksum(checked: number[]): [number, number] {
    const sum = checked.reduce((a, b) => a + (b & 0xff), 0) & 0xffff
    const c = (0x10000 - sum) & 0xffff
    return [(c >> 8) & 0xff, c & 0xff]
  }
  ```
- **读参数**：`DD A5 FA 03 [regHi] [regLo] [count] [chk] 77`
- **写参数（需工厂模式）**：`DD 5A FA [2N+3] [regHi] [regLo] [N] [data...] [chk] 77`
- **进/出工厂模式**：`DD 5A 00 02 56 78 [chk] 77` / `DD 5A 01 02 28 28 [chk] 77`
- **状态位**：`0x00` 成功；`0x80` 命令不存在；`0x81` 操作错误（未进工厂/密码不符）；`0x82` 校验错；`0x83` 密码错。
